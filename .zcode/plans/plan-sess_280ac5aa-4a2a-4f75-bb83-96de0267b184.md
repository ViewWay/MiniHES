# MiniHES MongoDB 集成设计方案

## 一、背景与目标

### 现状分析
| 层面 | 现状 | 问题 |
|------|------|------|
| **MongoDB 连接** | `motor==3.6.0` 已在 `pyproject.toml` 声明，但 app 代码从未 import | 依赖声明了却未使用 |
| **PG-MongoDB 桥梁** | `col_session` 表有 `mongo_db`/`mongo_collection`/`mongo_doc_id` 字段，seed 数据有真实指针 | 纯指针，后端无 Mongo 客户端读写 |
| **分析 API** | 9 个路由全部返回 hardcoded stub | 前端 `analysis/*` 页面全部降级到 mock |
| **真实数据格式** | `docs/testdata/template_meter.json` (1.2MB) 完整记录 DLMS 采集文档结构 | 格式确定，可直接作为 schema 设计依据 |
| **InfluxDB** | 已弃用，时序汇总在 PG `col_meter_reading`/`col_reading_daily` | PG 承担结构化读数 + 汇总 |

### 设计目标
1. **MongoDB 作为原始采集文档存储** — 完整保留 DLMS 采集会话文档（24 sheets / 720 KV pairs / Profile buffers），不拆解、不丢失
2. **落地 PG-MongoDB 桥梁** — 让 `col_session` 的 `mongo_*` 字段成为真正可查询的指针
3. **分析 API 真实化** — 从 MongoDB 文档中查询 Daily Billing 日线、Load Profile 负荷曲线、Instantaneous Data 瞬时量，替代当前 stub
4. **保持 PG 权威** — PG 仍为系统主库（用户/设备/任务/权限/结构化读数/汇总），Mongo 仅存"原始大文档"

## 二、集合（Collection）Schema 设计

### 2.1 核心集合：`meter_sessions`

**用途**：存储每次 DLMS 采集会话的完整原始文档，对应 `col_session.mongo_doc_id` 指向的文档。

**设计依据**：直接映射 `template_meter.json` 的真实结构。

```
Database:   minihes                    ← 统一用一个 DB（不再按项目名分库）
Collection: meter_sessions             ← 每次采集 = 1 个文档
```

**文档结构**：
```javascript
{
  _id: ObjectId("..."),

  // === 采集会话元数据（可索引、可查询） ===
  session_id: 42,                      // PG col_session.id（反向定位）
  meter_id: 3,                         // PG dev_meter.id
  meter_serial: "KFM1020110000001",    // 电表编号（冗余，方便无 JOIN 查询）
  project_id: 1,                       // PG dev_project.id
  project_name: "Puma-01",             // 项目名（冗余）
  task_id: null,                       // PG col_task.id（nullable）

  // === 采集时间 ===
  collected_at: ISODate("2025-11-01T09:33:56Z"),   // 采集时刻
  imported_at: ISODate("2026-07-10T..."),          // 入库时刻

  // === 来源 ===
  source: "import",                    // auto / manual / import
  source_file: "XMLFunctionLists_Meter_PP.xlsx",
  connection_type: "HDLC",             // HDLC / TCP / WPDU / FEP

  // === 采集结果摘要（冗余自 col_session） ===
  status: "success",                   // success / partial / failed
  total_points: 720,
  success_points: 718,
  failed_points: 2,

  // === DLMS 原始数据：sheets（完整保留，不拆解） ===
  sheets: {
    "Clock": {
      sheet_name: "Clock",
      objects: [
        {
          key: "Clock.Clock.Time",
          classId: 8,
          obis: "0.0.1.0.0.255",
          obisFormatted: "0-0:1.0.0.255",
          attributeId: 2,
          attributeName: "Time",
          controlName: "Clock",
          value: "2025-11-10 01 15:38:38 00,FFC4,00",
          timestamp: ISODate("..."),
          status: "success"
        },
        // ... 9 objects
      ]
    },
    "Energy": { objects: [...] },           // 6 objects — 电能累计量
    "Instantaneous Data": { objects: [...] }, // 60 objects — 瞬时 V/I/P/PF
    "Daily Billing": { objects: [...] },     // 40 objects — 含 365 天 buffer
    "Month Billing": { objects: [...] },     // 40 objects — 含 12 月 buffer
    "Load Profile": { objects: [...] },      // 47 objects — 含 96 点 buffer
    "Event Record": { objects: [...] },      // 86 objects — 事件日志
    // ... 共 24 sheets 完整保留
  },

  // === key_value_pairs 扁平索引（保留原始 720 KV） ===
  key_value_pairs: {
    "Clock.Clock.Time": "2025-11-10 01 15:38:38 00,FFC4,00",
    "Energy.Cumulative A Positive.Value": 1529384,
    "Instantaneous Data.Instantaneous Voltage L1.Value": 231,
    // ... 720 pairs
  },

  // === summary ===
  summary: {
    total_sheets: 24,
    total_objects: 720,
    total_success: 718,
    total_failed: 2,
    duration_ms: 45230
  },

  // === 文档版本 ===
  schema_version: 1
}
```

**文档大小**：~1.2 MB（在 16MB 限制内，安全）

**索引设计**：
```javascript
// 主查询路径：按电表 + 时间查最新/历史采集

// 按项目 + 时间范围批量查
db.meter_sessions.createIndex(

  { name: "idx_project_time" }
```

### 2.2 辅助集合：`meter_events`（可选，Phase 2）

**用途**：从 Event Record sheet 拆出的结构化事件，供告警引擎和分析 API 快速查询。

```javascript
{
  _id: ObjectId("..."),
  session_id: 42,                      // 关联采集会话
  meter_id: 3,
  meter_serial: "KFM1020110000001",
  event_code: 0x00010000,              // DLMS event code
  event_name: "Power up",
  event_time: ISODate("2025-06-15T03:00:00Z"),
  severity: "info",                    // info / warning / critical
  raw: { ... }                         // 原始 object 完整保留
}
```

> **决策**：Phase 1 不建此集合。Event Record 直接从 `meter_sessions.sheets["Event Record"]` 查询即可（86 objects 量级不大）。如果后续告警引擎需要高频查事件，再拆出。

## 三、应用层架构

### 3.1 MongoDB 连接层

**新增文件**：`backend/app/core/mongo.py`

```python
"""MongoDB 异步客户端（motor）。

职责：
  - 单例 AsyncIOMotorClient（进程级连接池）
  - 提供 get_mongo() 依赖注入
  - 读取 MONGODB_URL 环境变量
"""
from motor.motor_asyncio import AsyncIOMotorClient, AsyncIOMotorDatabase

from app.core.config import settings

_client: AsyncIOMotorClient | None = None


def get_mongo_client() -> AsyncIOMotorClient:
    global _client
    if _client is None:
        _client = AsyncIOMotorClient(settings.MONGODB_URL)
    return _client


def get_mongo_db() -> AsyncIOMotorDatabase:
    return get_mongo_client()[settings.MONGODB_DATABASE]


async def get_mongo() -> AsyncIOMotorDatabase:
    """FastAPI 依赖注入入口。"""
    return get_mongo_db()


async def close_mongo():
    global _client
    if _client:
        _client.close()
        _client = None
```

### 3.2 数据访问层：`MongoSessionRepository`

**新增文件**：`backend/app/services/mongo_session_repo.py`

核心方法（均 async）：
```python
class MongoSessionRepo:
    def __init__(self, db: AsyncIOMotorDatabase):
        self.col = db["meter_sessions"]

    async def insert_session(self, doc: dict) -> str:
        """写入完整采集文档，返回 _id（hex）"""

    async def get_by_doc_id(self, mongo_doc_id: str) -> dict | None:
        """按 col_session.mongo_doc_id 查原始文档"""

    async def get_latest_by_meter(self, meter_id: int) -> dict | None:
        """查某电表最新一次采集文档（分析 API 常用）"""

    async def get_kv_value(self, meter_id: int, key: str) -> any:
        """查 key_value_pairs 中某个 key 的值（如 'Energy.Cumulative A Positive.Value'）"""

    async def get_daily_billing(self, meter_id: int, days: int = 30) -> list[dict]:
        """从 Daily Billing sheet 的 buffer 中提取日用电曲线"""

    async def get_load_profile(self, meter_id: int) -> list[dict]:
        """从 Load Profile sheet 的 buffer 中提取 96 点负荷曲线"""

    async def get_instantaneous(self, meter_id: int) -> dict:
        """从 Instantaneous Data sheet 提取 V/I/P/PF 等瞬时量"""

    async def get_sessions_by_date_range(
        self, meter_id: int, start: datetime, end: datetime
    ) -> list[dict]:
        """按时间范围查历史采集文档列表"""
```

### 3.3 分析 Service 层改造

**新增文件**：`backend/app/services/analysis_service.py`

将 analysis API 的业务逻辑从 hardcoded → 从 MongoDB 查询：

```python
class AnalysisService:
    def __init__(self, db: AsyncSession, mongo_repo: MongoSessionRepo):
        self.db = db       # PG（查电表名/项目名等元数据）
        self.mongo = mongo_repo  # Mongo（查原始采集数据）

    async def daily_analysis(self, meter_id: int, date: date | None = None):
        # 1. PG 查电表元信息
        meter = await self.db.get(Meter, meter_id)
        # 2. Mongo 查最新采集文档
        doc = await self.mongo.get_latest_by_meter(meter_id)
        # 3. 从 sheets["Daily Billing"] 提取日线数据
        daily = self._parse_daily_billing(doc, date)
        # 4. 从 sheets["Instantaneous Data"] 提取瞬时量
        inst = self._parse_instantaneous(doc)
        return { "meter_id": meter_id, "meter_name": meter.meter_name, ...daily, ...inst }

    async def load_profile(self, meter_id: int):
        """96 点负荷曲线"""

    async def compare_meters(self, meter_ids: list[int], metric: str):
        """多表对比"""

    async def consistency_check(self, project_id: int):
        """数据一致性检查（采集覆盖率 + 电能平衡校验）"""
```

### 3.5 采集写入路径

**修改文件**：`backend/app/services/collector/` 下新建 `session_writer.py`

当采集任务执行完成（未来真正的 DLMS 采集引擎跑完后），或 Excel 导入完成时：

```python
async def save_collection_session(
    db: AsyncSession,
    mongo_repo: MongoSessionRepo,
    meter_id: int,
    raw_doc: dict,          # 即 template_meter.json 那种完整结构
    source: str = "import",
    source_file: str = "",
) -> CollectionSession:
    """将原始采集文档写入 Mongo，并在 PG col_session 创建桥梁记录。"""
    # 1. Mongo 写入
    mongo_id = await mongo_repo.insert_session({
        **_build_metadata(meter_id, ...),
        "sheets": raw_doc["sheets"],
        "key_value_pairs": raw_doc["key_value_pairs"],
        "summary": raw_doc.get("summary", {}),
        "schema_version": 1,
    })

    # 2. PG 桥梁记录
    session = CollectionSession(
        meter_id=meter_id,
        mongo_db=settings.MONGODB_DATABASE,
        mongo_collection="meter_sessions",
        mongo_doc_id=mongo_id,
        source=source,
        source_file=source_file,
        status="completed",
        total_read=raw_doc["summary"]["total_objects"],
        total_success=raw_doc["summary"]["total_success"],
        ...
    )
    db.add(session)
    await db.flush()
    return session
```

## 四、Schema 验证（MongoDB Validator）

为 `meter_sessions` 集合添加 `$jsonSchema` 验证器，在数据库层面保证文档完整性：

```javascript
db.createCollection("meter_sessions", {
  validator: {
    $jsonSchema: {
      bsonType: "object",
      required: ["meter_id", "collected_at", "sheets", "schema_version"],
      properties: {
        meter_id:       { bsonType: "int", description: "PG dev_meter.id" },
        meter_serial:   { bsonType: "string" },
        collected_at:   { bsonType: "date" },
        imported_at:    { bsonType: "date" },
        source:         { enum: ["auto", "manual", "import"] },
        sheets:         { bsonType: "object" },
        key_value_pairs:{ bsonType: "object" },
        schema_version: { bsonType: "int", minimum: 1 },
        status:         { enum: ["success", "partial", "failed"] }
      }
    }
  },
  validationLevel: "moderate",   // 已有文档不强制验证
  validationAction: "warn"       // 先 warn，观察稳定后改 error
})
```

## 六、PG 与 MongoDB 职责划分

| 数据类型 | 存储 | 理由 |
|---------|------|------|
| 用户/角色/权限/部门 | **PG** | 关系型，强一致性，ACID |
| 设备元数据(CRUD) | **PG** | 结构化，频繁更新 |
| 采集任务配置 | **PG** | 结构化 + JSONB 混合 |
| OBIS 模板 | **PG** | 结构化 + JSONB |
| 点值读数(结构化) | **PG** `col_meter_reading` | 索引查询高效，已建好 |
| 日/月汇总 | **PG** `col_reading_daily` | 聚合查询高效 |
| 数据质量统计 | **PG** `col_data_quality` | 小数据量结构化 |
| **DLMS 原始采集文档** | **MongoDB** `meter_sessions` | 1.2MB 大文档，24 sheets 灵活结构 |
| **Profile buffers(日线/负荷曲线)** | **MongoDB** | 嵌在采集文档中，天然时序 buffer |
| **720 KV pairs** | **MongoDB** | 扁平 key-value，灵活查询 |
| 告警规则与记录 | **PG** | 结构化，关联用户/电表 |
| 审计日志 | **PG** | JSON diff，事务一致性 |

## 九、风险与缓解

| 风险 | 影响 | 缓解 |
|------|------|------|
| Mongo 未启动时服务 crash | 全站不可用 | `get_mongo()` 懒加载；分析 API try/catch 降级返回空 + warning |
| 文档 > 16MB（极端电表） | 写入失败 | `insert` 前检查 `$bsonSize`；超大文档拆分 Profile buffer 到独立集合 |
| seed.py 需要 Mongo 才能跑 | 新开发者环境初始化复杂 | seed.py 检测 Mongo 可用性：不可用时跳过 Mongo 写入，仅 seed PG |
| 分析 API 性能 | 大文档每次加载 1.2MB | Mongo projection 只取需要的 sheet（`{sheets.Daily Billing: 1}`）|
| PG-Mongo 数据不一致 | 悬空指针 | 删除 session 时同步删 Mongo doc（或标记 orphan 由 GC 清理）|
