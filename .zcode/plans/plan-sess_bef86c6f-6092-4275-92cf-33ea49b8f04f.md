# 每日分析重新设计：项目 → 设备 → 日期范围

## 问题
当前 `daily.vue` 界面只有一个 `meter_id` 输入框 + 单日期选择器，用户需要手动知道电表 ID。不符合实际业务流程。

## 正确流程
**选项目 → 选设备（该项目下的设备列表）→ 选日期范围 → 查看采集数据**

## MongoDB 数据现状
- `meter_sessions` 集合按 `project_name` 分 3 个项目，每项目 8 台电表
- 每个文档有 `meter_id`（关联 PG）、`collected_at`（采集时间）、`key_value_pairs`（280 个 OBIS 点）
- 支持 `get_sessions_by_date_range(meter_id, start, end)` 按时间范围查询

---

## 后端改动（2 个文件）

### 1. `analysis_mongo_service.py` — 改 `daily_analysis` 方法

**当前签名：** `daily_analysis(meter_id, target_date)` — 单表单日

**改为：** `daily_analysis(meter_id, date_from, date_to)` — 单表日期范围

- 查 MongoDB `get_sessions_by_date_range(meter_id, start, end)` 获取范围内所有采集文档
- 生成每日趋势数据（每天一条：总电能、日增量、电压均值等）
- 返回多日数据列表而非单日快照

### 2. `analysis.py` — 改 `/daily` 路由参数

```
# 旧
GET /analysis/daily?meter_id=1&date=2025-06-15

# 新
GET /analysis/daily?meter_id=1&date_from=2025-06-01&date_to=2025-06-15
```

新增辅助端点（可选）：
```
GET /analysis/daily/meters?project_id=1  → 返回该项目下有采集数据的电表列表
```

---

## 前端改动（2 个文件）

### 3. `api/modules/analysis.ts` — 更新接口参数

```ts
export interface DailyAnalysisParams {
  meter_id: number;
  date_from: string;   // 新增
  date_to: string;     // 新增
}
```

### 4. `views/analysis/daily.vue` — 重构筛选栏

**旧 UI：** `[设备ID输入框] [日期选择器] [查询]`

**新 UI：**
```
[项目下拉框(从 getProjectList)] → [设备下拉框(该项目下的设备)] → [日期范围选择器] → [查询]
```

- 项目变化时自动加载设备列表（`getMeterList({project_id})`)
- 日期范围默认最近 7 天
- 结果区展示多日数据：每日趋势图（X 轴日期，Y 轴电能增量）+ 每日明细表
