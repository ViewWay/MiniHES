# MiniHES 项目开发流程

> 综合标准软件工程流程和前端开发实践，定义 MiniHES 项目全流程规范。

## 流程总览

```
需求对接 → 需求评审 → 视觉评审 → 技术方案 → 排期评估 → 概要设计
    → 开发（前端视觉构建 + 后端接口开发）→ 前后端联调 → 自测
    → 产品体验 → 代码Review → 视觉走查 → 提测 → Bug修复 → 上线
```

### 4. 技术方案协商

前后端各自明确技术方案并协商接口：

| 模块 | 前端方案 | 后端方案 |

| 框架 | Vue 3 + Ant Design Vue | FastAPI + SQLAlchemy async |
| 构建 | Vite | uv |
| 状态管理 | Pinia | Redis |
| 数据可视化 | ECharts | PostgreSQL 时序表 |
| API 通信 | requestClient | RESTful + JWT |

**接口协商要点**：
- API 路径和方法（RESTful 规范）
- 请求/响应数据结构（`{code, message, data}` 统一格式）
- 业务错误码定义（10001-30999 分模块）
- 分页、排序、筛选参数
- 认证方式（JWT Bearer Token）

## Git 工作流

```
main
├── develop              ← 开发主线
│   ├── feature/auth     ← Phase 1
│   ├── feature/meter    ← Phase 2
│   ├── feature/task     ← Phase 3
│   ├── feature/analysis ← Phase 4
│   └── feature/test     ← Phase 5
```

- 每个 Phase 一个 feature 分支，完成后 PR 合并到 develop
- develop 稳定后合并到 main
- 提交规范：`feat:` / `fix:` / `docs:` / `refactor:` / `test:` / `chore:`
